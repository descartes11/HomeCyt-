================================================================================
  MaCité — Endpoints API nécessaires au backend
  Version 1 · 13 novembre 2026
================================================================================

Ce document liste les appels HTTP dont l'application Flutter MaCité a besoin
pour remplacer ses données de démonstration (aujourd'hui en mémoire dans
lib/features/*/..._store.dart) par un vrai serveur.

Chaque endpoint indique : la méthode, le chemin, qui peut l'appeler, ce qu'il
reçoit et ce qu'il renvoie, et l'écran de l'app qui l'utilise.


--------------------------------------------------------------------------------
0. CONVENTIONS GÉNÉRALES
--------------------------------------------------------------------------------

URL de base      https://<domaine>/api/v1
Format           JSON (UTF-8). Envoi de fichiers : multipart/form-data.
Authentification En-tête  Authorization: Bearer <access_token>
                 (sauf les endpoints marqués « public »).
Rôles            LANDLORD (bailleur) · TENANT (locataire).
                 Un bailleur ne voit que SA cité ; un locataire ne voit que
                 SES données et celles de SA cité.
Montants         Entiers en FCFA (ex. 45000), jamais de décimales.
Dates            ISO 8601 (ex. "2026-11-04T09:12:00Z", "2026-12-01").
                 L'app se charge de l'affichage en français (« 4 nov. »).
Téléphones       Chaîne de chiffres sans espaces (ex. "0712345602").
                 L'app accepte les espaces à la saisie et les retire avant envoi.
Mois             Format "AAAA-MM" (ex. "2026-11") pour les loyers.
Pagination       ?page=1&per_page=20  →  { "items": [...], "page": 1,
                 "per_page": 20, "total": 48 }
Erreurs          Code HTTP + corps :
                 { "error": { "code": "INVALID_PHONE",
                              "message": "Numéro invalide : 8 chiffres minimum.",
                              "field": "phone" } }
                 Le champ "message" est affiché tel quel sous le champ
                 concerné : le rédiger en français.
                 Codes HTTP utilisés : 400 données invalides · 401 non connecté
                 ou jeton expiré · 403 interdit · 404 introuvable ·
                 409 conflit (doublon) · 413 fichier trop lourd · 422 règle
                 métier non respectée · 500 erreur serveur.
Hors ligne       Si le serveur ne répond pas, l'app affiche le bandeau
                 « Pas de connexion internet » et un bouton « Réessayer ».


--------------------------------------------------------------------------------
1. AUTHENTIFICATION ET COMPTES          (écrans : auth_flow.dart)
--------------------------------------------------------------------------------

POST   /auth/login                                                    public
       Corps : { "identifier": "0712345602" | "sarah.m@mail.com",
                 "password": "..." }
       Renvoie : { "access_token", "refresh_token", "expires_in",
                   "user": { "id", "role": "LANDLORD"|"TENANT", "name",
                             "phone", "email", "city_id" } }
       Le champ "role" décide quel espace l'app ouvre (bailleur ou locataire).
       Erreurs : 401 INVALID_CREDENTIALS ·
                 403 ACCOUNT_PENDING (locataire pas encore validé par le
                 bailleur) · 403 ACCOUNT_REJECTED.

POST   /auth/refresh                                                  public
       Corps : { "refresh_token" }   Renvoie : { "access_token", "expires_in" }

POST   /auth/logout
       Corps : { "refresh_token" }   Renvoie : 204
       (bouton « Se déconnecter » des paramètres)

POST   /auth/password/forgot                                          public
       Corps : { "identifier" }      Renvoie : 204 (toujours, même si le
       compte n'existe pas). Envoie un lien ou un code par SMS / e-mail.
       (écran « Mot de passe oublié »)

POST   /auth/password/reset                                           public
       Corps : { "token" | "code", "identifier", "new_password" }
       Règle : 8 caractères minimum, dont un chiffre.

GET    /me
       Renvoie l'utilisateur connecté (même forme que "user" ci-dessus) +
       pour un locataire : { "room_id", "room_number", "building_name",
                             "city_name" }.

PATCH  /me
       Corps (champs facultatifs) : { "name", "phone", "email" }
       (bouton « Modifier le profil »)

POST   /me/password
       Corps : { "current_password", "new_password" }

POST   /me/devices                       (notifications push, à prévoir)
       Corps : { "push_token", "platform": "android"|"ios"|"web" }

--- Inscription d'un BAILLEUR ---

POST   /auth/register/landlord                                        public
       Corps : { "name", "phone", "email", "password" }
       Renvoie : comme /auth/login (le compte est actif tout de suite).
       Erreurs : 409 PHONE_TAKEN · 409 EMAIL_TAKEN.

--- Inscription d'un LOCATAIRE (validée ensuite par le bailleur) ---

GET    /cities?q=jardins                                              public
       Recherche de cité (étape « Choisissez votre cité »).
       Renvoie : [ { "id", "name", "area", "owner_name",
                     "free_rooms_count" } ]

GET    /cities/{city_id}/rooms/free                                   public
       Chambres libres proposées dans la liste « Chambre ».
       Renvoie : [ { "id", "number": "A-104", "type": "Studio",
                     "rent": 45000 } ]

POST   /auth/register/tenant                       public · multipart
       Champs : name, phone, email, password, city_id, room_id,
                cni_number, job, org (facultatif),
                cni_photo (fichier JPG/PNG, recto lisible)
       "job" ∈ Étudiant(e) · Salarié(e) · Fonctionnaire ·
               Travailleur indépendant · Commerçant(e) ·
               En recherche d’emploi · Autre
       Renvoie : 201 { "registration_id", "status": "PENDING" }
       Effet : crée une demande visible par le bailleur (section 3).
       Le locataire ne peut pas se connecter avant la validation.

4. BAILLEUR · LOCATAIRES        (écrans : TenantsScreen, TenantDetail,
                                 AddTenant)                         LANDLORD
--------------------------------------------------------------------------------

GET    /landlord/tenants?q=david&status=all|ok|late&building=A
       Recherche (nom ou chambre), filtre « À jour / En retard »,
       filtre par immeuble.
       Renvoie : [ TenantSummary ]
       TenantSummary = { "id", "name", "initials", "room_number",
                         "building", "rent", "paid_this_month",
                         "status": "paid"|"partial"|"late",
                         "days_late", "has_proof_to_verify",
                         "proof_amount" }

GET    /landlord/tenants/{id}
       Renvoie : TenantSummary + { "job", "org", "phone", "email",
                 "since", "lease": { "start", "end", "months",
                 "free_months" }, "id_document": { "type", "number",
                 "photo_url" }, "emergency_contact", "note" }

GET    /landlord/tenants/{id}/rents
       Historique des loyers (6 derniers mois ou paginé).
       Renvoie : [ { "month": "2026-10", "amount", "paid", "paid_on",
                     "status", "receipt_available": true } ]

POST   /landlord/tenants
       Ajout manuel d'un locataire (formulaire « Ajouter un locataire »).
       Corps : { "name", "phone", "id_number", "room_id",
                 "start_date": "2026-12-01",
                 "duration_months": 1..12,
                 "free_months": 0..(duration_months - 1) }
       Règles : chambre libre obligatoire ; au moins un mois payé
                (free_months < duration_months) ; les mois offerts sont
                les premiers du bail ; caution = 1 mois de loyer.
       Effet : SMS d'invitation au locataire (installer l'app, se
               connecter avec son numéro).
       Renvoie : 201 { "id" }
       Erreurs : 409 ROOM_NOT_FREE · 409 PHONE_TAKEN · 422 INVALID_FREE_MONTHS

PATCH  /landlord/tenants/{id}/note
       Corps : { "note": "Préfère être contacté par message après 18 h." }

POST   /landlord/tenants/{id}/remind
       Relance de loyer par SMS. Renvoie : 204

GET    /landlord/tenants/{id}/id-document
       URL signée (durée courte) de la photo de la pièce d'identité.

17. TÂCHES AUTOMATIQUES CÔTÉ SERVEUR (pas d'endpoint, mais nécessaires)
--------------------------------------------------------------------------------

- Le 2 de chaque mois : rappel aux locataires dont le loyer n'est pas payé
  (si « reminder_before_due » est activé chez le bailleur).
- Le 8 de chaque mois : relance SMS des loyers impayés
  (si « auto_reminder » est activé).
- Chaque jour : calcul des jours de retard (« days_late ») et du statut
  "late" des chambres.
- Mois offerts : ne pas réclamer de loyer ni relancer pendant ces mois.
- Envoi des SMS (inscription validée/refusée, invitation d'un locataire
  ajouté par le bailleur, annonces, alertes urgentes) via un fournisseur
  SMS local.
